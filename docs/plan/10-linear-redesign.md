# 10 · Linear 风格改版与信息架构收敛

三件事一起做的：**全站换成 Linear 的设计语言**、**登录后改为侧边导航布局**、
**前端不再出现「工作区」概念**。

前两件是外观与布局，第三件是信息架构——放在一起是因为它们改的是同一批文件。

---

## 1. 设计语言：Linear

色板与排版取自 Linear 的公开设计令牌。它的观感来自三条规则，不是某个具体颜色：

| 规则 | 落地方式 |
|---|---|
| **层次靠 surface 阶梯，不靠阴影** | 全站不写 `shadow-*`。卡片 = 比底色高一层的填充 + 1px hairline。暗色四级阶梯 `#010102 → #0f1011 → #141516 → #18191a` |
| **display 标题配激进负字距** | 约字号的 4%（80px 收 -3px）。`.display-xl/lg/md` 三个类，`clamp()` 随视口缩放，行高同步收紧到 1.05~1.15 |
| **单色系统** | 薰衣草 `#5e6ad2` 只出现在品牌标记、主 CTA、focus ring。唯一的彩色例外是 `semantic-success #27a644`（状态点） |

配套细节：按钮一律 8px 圆角（**从不做胶囊**）、`eyebrow` 小标签用**正**字距（+0.03em，
与大标题的负字距相反）、正文用 ink-muted `#d0d6e0` 而不是最亮的 `#f7f8f8`——
后者留给标题，这一档差别正是它耐看的原因。

配色**跟随主题**（而非营销页锁死深色）：Linear 自己也给了整套亮色反转色板，
上面三条在亮色下同样成立。

### 1.1 实现方式

全部落在 `web/src/style.css` 的 `@theme` 块里，改的是 **Kumo 令牌本身**，
组件代码继续只写 `bg-kumo-base` 这类语义类——没有一个组件里写死颜色，
ESLint 那条禁止原始色类的规则不用开任何口子，暗色也自动成立。

两个已知陷阱（都写在 style.css 的注释里）：

- Kumo 在自己的 `@layer base` 里还有一份同名令牌。我们赢是因为 `@theme` 编译后落在
  **无 layer** 的 `:root` 上，CSS 层叠规定 unlayered 优先于 layered——不是因为写在后面。
- Kumo 的 primary Button 会对 brand 做 `color-mix(brand, white 30%)`，
  所以按钮比 Linear 的实心紫**略淡一档**。这是有意的取舍：反推「混合后正好等于 #5e6ad2」
  的原值是 `oklch(38.2% 0.226 275)`，深得离谱，会把链接和 focus ring 一起拖暗。

## 2. 布局：侧边导航取代顶栏

登录后**没有顶栏**，所有全局入口收进左侧常驻导航栏。

```
┌────────┬──────────────────────────────────────┐
│ 品牌    │                                      │
│         │                                      │
│ 邮箱    │            内容区                     │
│ 导入    │   （/mail 自身不滚，其余页面滚）        │
│ 令牌    │                                      │
│ 标签    │                                      │
│         │                                      │
│ 用量    │                                      │
│ 后台*   │                                      │
│ ───     │                                      │
│ 主题    │                                      │
│ 收起    │                                      │
│ 头像    │                                      │
│ 退出    │                                      │
└────────┴──────────────────────────────────────┘
  224px ⇄ 56px
```

- **可伸缩**：展开 224px / 收起 56px（只剩图标，靠 `title` 提示），偏好记在 localStorage。
- **窄屏强制图标模式**：`<768px` 时宽度锁死 56px。420px 的屏幕上一条 224px 的导航栏
  会吃掉一半宽度，剩下的连账号列表都放不下。用 CSS 断点而不是 `matchMedia`——
  JS 里再写一个 768 就多一个真源，迟早和 Tailwind 的断点对不上。
- 主题切换、账号入口、退出都在导航栏底部。

### 2.1 三种页面形态

由路由 `handle` 声明（`src/router/handle.ts`），`Layout` 据此分流：

| handle | 形态 | 用于 |
|---|---|---|
| 无 | 顶栏 + 文档流 + 页脚 | 首页、登录、注册、法务 |
| `appRoute` | 侧边栏 + 可滚内容区 | 设置、导入、令牌、分组、用量、后台 |
| `shellRoute` | 侧边栏 + **不滚**内容区 | `/mail` 工作台（滚动由内部面板各自负责） |

公开页保留一条极简顶栏：访客身上没有导航栏，登录入口必须摆在看得见的地方。

三个方向都由 `Layout.test.tsx` 钉住——漏给某个页面挂 handle 的症状是
「这个页面突然没了导航栏、还冒出一个顶栏」，很容易被当成 CSS 问题去查样式。

## 3. 前端隐藏「工作区」

一个用户就是一个工作区，界面上不再提这个概念。

**后端与数据模型一律不动**：多租户表结构、API 的 `tenantID`、`tenantStore`、
`RouteGuards` 里的 `hydrate` 全部原样保留。以后要做团队协作时，把两个页面挂回路由即可。

| 改动 | 说明 |
|---|---|
| 删除 `DashboardPage` | 整页就是工作区切换器 + 当前工作区卡片 + 成员入口，拿掉这些就空了。登录后直接落到 `/mail` |
| `TenantSettingsPage` / `TenantMembersPage` | **文件保留，路由和入口移除**。等团队功能时挂回来 |
| 删除 `AdminTenantsPage` | 后台的「工作空间」列表和「用户」列表是同一批行，见 §3.1 |
| `WorkspaceSettingsPage` → `UsagePage` | 它其实是配额页，跟工作区无关。路由 `/settings/workspace` → `/settings/usage`，标题「用量」 |
| 界面文案 | 「本工作空间全部账号」→「全部账号」、「正在加载工作空间…」→「正在加载…」等 |
| 法务页 | 「工作空间之间完全隔离」→「不同用户之间完全隔离」等**等价表述**，隔离承诺本身没变 |

### 3.1 管理后台：两份清单合并成一份

**一个租户空间只属于一个用户**，所以后台的「工作空间」列表和「用户」列表原本是
同一批行的两种叫法——两份清单摆在一起，只会让人怀疑「这两个数为什么对不上」。

`AdminTenantsPage` 已删除，它的两件事并进了用户页的行操作：

- **配额调整**：`QuotaDialog` 的入参从 `AdminTenant` 改成了一个最小的 `QuotaTarget`
  （`tenantID` / `title` / `subtitle`），不再绑定某个具体的列表行类型。
- **进入其邮箱**：链接文字是「进入邮箱」而不是「邮箱」——左侧导航栏里已经有一个「邮箱」，
  同名两处指向完全不同的地方，很容易点错（连验证脚本都点错了一次）。

为此给 `AdminUser` 补了 `plan_code` / `max_accounts` / `over_quota`：

- 两个引擎的 `ListAdminUsersPage` 与 `GetAdminUser` 各加两个 `LEFT JOIN`
  （`tenant_quotas` + `plans`）和两列，`make sqlc-generate` 重新生成。
- `over_quota` 沿用租户那边的算法，在 repo 组装后调 `ComputeOverQuota()`。

**为什么不在前端合并两个请求**：`users` 和 `tenants` 各自分页，users 第 1 页的用户
其空间可能落在 tenants 的第 3 页，前端拼不出完整的一行。

其余清理：`AdminShell` 去掉「工作空间」tab、总览去掉与用户数重复的「工作空间」统计、
管理员邮箱视图的返回链接指向用户列表、Banner 改为显示「这个空间是谁的」
（查 users 而不是 tenants，前端因此不再依赖 `adminApi.tenants`）。

顺手修了一个既有小 bug：用户页的状态筛选下拉用 `<Select.Option>` 子元素时
`value=""` 选不中，显示成一片空白，看起来像坏了——改用 `items` 形式（其余页面都是这么写的）。

## 4. 验证

- 前端：构建 / ESLint / 40 条测试全过。
- Go：构建 / vet / golangci-lint 0 issues / 11 个包测试全过（§3.1 动了 sqlc 查询与 repo）。
  `make sqlc-verify` 会因为生成物尚未提交而报错，那是它的设计——生成物本身是最新的。
- 真实浏览器（Playwright，独立临时库）：
  - 登录后**无顶栏、无页脚**，侧边导航 224px，点击收起变 56px，偏好持久化。
  - 注册后直接落到 `/mail`；`/dashboard` 及所有相关引用零残留。
  - **全站**（含管理后台）「工作区 / 工作空间」字样零残留。
  - 后台用户页：表头为 用户 / 邮箱·上限 / 套餐 / 状态 / 操作；
    配额弹窗从用户行打开并显示正确的用户；「进入邮箱」跳到该用户的空间，
    Banner 显示的所有者与 URL 里的 tenantID 一致。
  - 亮/暗两套都验证过，暗色由侧边栏按钮切换。
  - 三档断点（1440 / 1024 / 420）均无整页横向或纵向滚动；420 下导航自动收成 56px。

### 4.1 顺手修的两处

- **中栏分页条换行**：四栏都展开时账号列表只有 400 多像素，
  完整的「第 1–50 条，共 200 条」会把分页挤到换行。按 `@container` 分两档，
  窄的时候只显示总数——用户先想知道一共多少个。
- **两块同色面板黏连**：全局导航和 `/mail` 的分组栏都用 `canvas`，贴在一起糊成一片。
  分组栏改用 `base`，层次才分得开。

## 5. 改版后的一轮体检

把所有页面渲染出来量了一遍，找到的问题（都不是主观感觉，有数据）：

### 5.1 内容起始线有五种

改版前量到的左边距：导入 48px、令牌 96px、设置三页 224px、后台三页 32px，
标题字号还有三档。在侧边栏布局里连着切几个页面，标题会横着跳近 200px 还变大小。

新增 `PageShell` 统一：外层一律 `max-w-6xl` 居中，所有页面标题落在同一条竖线上
（量得 9 个页面全部为左边距 32px / 宽 1152px）。内容需要更窄的（表单类）在 children
里自己限宽，**不要**改外层——那样标题会跟着挪，问题就又回来了。

`AdminShell` 与 `SettingsPage` 现在都只是 `PageShell` 加一组页签。
导入/令牌两页顺带去掉了「返回邮箱」链接：左侧导航栏里已经有了。

### 5.2 高度魔法数 `calc(100vh - 113px)`

`AuthCard` 和 `ErrorPage` 里都写着这个数（113 = 旧顶栏 56 + 旧页脚 57）。
顶栏没了之后它就不再对应任何东西，登录卡片因此偏上。
改法是让公开页的 `<main>` 成为 flex 容器，需要占满的页面用 `flex-1`——
不依赖任何具体数字（改完量得上下留白各 189px，对称）。

### 5.3 404 和渲染异常用了同一套文案

输错网址会看到「页面出错了」加一段 `No route matches URL ...`，像是自己碰坏了什么。
用 `isRouteErrorResponse` 分开：404 说「页面不存在」且不显示技术细节，
也不给「重新加载」按钮（404 重新加载还是 404）。两种情况都补上品牌标记和出口链接——
`ErrorPage` 挂在 `errorElement` 上，**不经过 Layout**，没有导航栏可用。

### 5.4 已登录的人在首页看到「免费开始」

点下去只会被守卫弹回工作台。根因不在文案：**首页是 index route，没挂守卫，
而恢复会话这件事当时是各个守卫自己做的**——所以没有守卫的页面根本不知道用户已经登录。

改成在 `Layout` 里统一恢复一次，守卫只读状态。公开页的顶栏与首页 CTA 现在都感知登录态
（已登录时三处都变成「进入邮箱」）。

顺带发现 `loadSession` 没有并发去重：StrictMode 把 effect 跑两遍时能看到两次一模一样的
`/auth/session`。加了在途 promise 复用，并配了回归用例
（`authStore.session.test.ts`，同时钉住「上一次结束后再调要重新取」）。
